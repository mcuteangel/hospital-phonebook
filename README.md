# دفتر تلفن بیمارستان

ابزار کار روزانه اپراتور سانترال: جستجوی فوری مخاطبین و داخلی‌های بیمارستان.
Node 22، **صفر دیپندنسی** (فقط `node:http`، `node:sqlite`، `node:crypto`، `node:test`)، بدون `npm install` و بدون بیلد.

> همه داده‌های نمونه (`seed.js`) **ساختگی**‌اند: موبایل `0900000xxxx`، تلفن `021555xxxxx`، کد ملی `000000xxxx` (عمداً نامعتبر)، ایمیل `@example.test`.

## اجرا

```bash
node seed.js          # (اختیاری) داده ساختگی برای دیدن برنامه
node server.js        # http://127.0.0.1:3001
```

- در **اولین اجرا** کاربر `admin` (دسترسی کامل) با رمز تصادفی ساخته و **یک بار** در ترمینال چاپ می‌شود. در اولین ورود، تغییر رمز عبور اجباری است؛ تا وقتی رمز عوض نشود، بقیه بخش‌ها باز نمی‌شوند.
- حساب نمایشی وجود ندارد؛ کاربران دیگر را با `node manage.js add-user` بسازید.
- ویندوز ۳۲بیتی بدون نصب: `node.exe` پرتابل v22 را کنار پوشه بگذارید و `node.exe server.js` را اجرا کنید.

### تنظیمات (متغیر محیطی)

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `PORT` | `3001` | پورت |
| `HOST` | `127.0.0.1` | برای دسترسی از شبکه داخلی `0.0.0.0` (بدون تغییر کد) |
| `DATA_DIR` | `../data` | پوشه دیتابیس؛ **بیرون** از پوشه برنامه. فایل: `directory.db` |

### مدیریت کاربران و پشتیبان

```bash
node manage.js list-users
node manage.js add-user <username> <operator|viewer>   # رمز تصادفی چاپ می‌شود
node manage.js set-password <username>
node manage.js backup                                  # یا دکمه «ساخت پشتیبان» در تب مدیریت
```

پشتیبان‌ها در `DATA_DIR/backups/` ذخیره می‌شوند (۳۰ نسخه آخر). ژورنال SQLite عمداً حالت پیش‌فرض است تا کپی دستی فایل `directory.db` هنگام بسته‌بودن سرور هم امن باشد.

## تست

```bash
node --test
```

## قانون طلایی داده حساس

- موبایل، تلفن منزل، ایمیل، آدرس و کد ملی فقط سمت سرور می‌مانند و فقط به **operator** با لاگین برمی‌گردند. `viewer` این فیلدها را نمی‌بیند و نمی‌تواند بر اساس آن‌ها جستجو یا فیلتر کند.
- فایل‌های استاتیک هیچ داده شخصی ندارند. `public/internals-snapshot.js` فقط **فهرست داخلی‌های بیمارستان** است و با هر تغییر داخلی‌ها خودکار بازنویسی می‌شود.
- اگر `public/index.html` را بدون سرور (`file://`) باز کنید یا سرور خاموش باشد، صفحه به «حالت آفلاین» می‌رود و فقط داخلی‌ها را (از همان snapshot) نشان می‌دهد.

## ساختار

```
server.js            سرور HTTP، مسیرها، سشن، هدرهای امنیتی
seed.js / manage.js  داده ساختگی / مدیریت کاربران
lib/                 db، auth (scrypt)، directory (منطق)، csv، text، snapshot، config
public/              فرانت‌اند خام (HTML/CSS/JS راست‌چین)
test/                تست‌های node:test
```

## API

| مسیر | دسترسی | توضیح |
|---|---|---|
| `POST /api/login` ، `POST /api/logout` ، `GET /api/me` | — | سشن با کوکی HttpOnly+SameSite=Strict |
| `POST /api/me/password` | کاربر | تغییر رمز |
| `GET /api/internals?q=` | **عمومی** | فهرست داخلی‌ها |
| `POST/PUT/DELETE /api/internals[/:id]` | operator | مدیریت داخلی‌ها |
| `GET /api/persons?q=&group=&type=&fav=1&limit=` | کاربر | جستجو/فیلتر (`type`: internal, direct, mobile, home) |
| `GET /api/persons/:id` | کاربر | جزئیات (فیلد حساس فقط operator) |
| `POST/PUT/DELETE /api/persons[/:id]` | operator | ویرایش |
| `PUT/DELETE /api/persons/:id/favorite` ، `POST /api/persons/:id/touch` ، `GET /api/recents` | کاربر | علاقه‌مندی و اخیرها (برای هر کاربر جدا) |
| `GET/POST/PUT/DELETE /api/groups[/:id]` | خواندن: کاربر، تغییر: operator | حذف گروه دارای مخاطب → ۴۰۹ |
| `GET /api/stats` | کاربر | «رکوردهای ناقص» فقط برای operator |
| `GET /api/export.csv` ، `POST /api/import` ، `POST /api/backup` | operator | CSV (UTF-8 با BOM) و پشتیبان |

## نکته‌ها

- جستجو ارقام فارسی/عربی و ی/ک عربی را یکسان می‌کند؛ نیم‌فاصله و اعراب نادیده گرفته می‌شود. اگر عبارت جستجو عدد باشد، فقط در شماره‌ها می‌گردد و کد داخلیِ دقیقاً برابر اول می‌آید.
- ورود CSV: ستون‌ها با عنوان فارسی (همان خروجی) یا انگلیسی (`first_name`, `last_name`, …) پذیرفته می‌شوند؛ جداکننده `,` `;` یا تب خودکار تشخیص داده می‌شود؛ ردیف تکراری (نام+نام خانوادگی+همه شماره‌ها) نادیده گرفته و گروه ناموجود ساخته می‌شود. در خروجی CSV سلول‌هایی که با `=` ‏`@` شروع شوند برای جلوگیری از اجرای فرمول در اکسل خنثی می‌شوند.
- اکسل صفر ابتدای شماره‌ها را هنگام باز کردن مستقیم CSV حذف می‌کند؛ برای ویرایش در اکسل، ستون‌های شماره را به‌صورت Text وارد کنید.
- سرور فقط روی `127.0.0.1` گوش می‌دهد و HTTPS ندارد؛ کوکی بدون `Secure` است. اگر `HOST=0.0.0.0` می‌گذارید، فقط در شبکه داخلی مورد اعتماد استفاده کنید.

## انتشار (Release)

- ادغام هر PR در main که کد برنامه را عوض کرده باشد، یک PR انتشار (`release/vX.Y.Z`) می‌سازد؛ Mergify آن را در صف ادغام می‌گذارد و پس از ادغام، تگ و Release گیت‌هاب با فایل zip برنامه ساخته می‌شود.
- تغییر فقط مستندات، انتشار نمی‌سازد. با `[skip release]` در پیام کامیت هم می‌شود انتشار را رد کرد.
- انتشار دستی: پوش تگ `v*` (انتشار کامل) یا dispatch دستی گردش‌کار Release (پیش‌نویس).

## اجرا روی ویندوز با لانچر (بدون نصب)

پوشه `launcher/` همان مدل شیفتیار است: بدون نصب و بدون ادمین.

1. یک پوشه بسازید (مثلاً `C:\phonebook`) و این دو فایل را آنجا بگذارید: `phonebook-launcher.cmd` و `update.ps1`.
2. پوشه `node` پرتابل v22 را به User Path اضافه کنید (همان کاری که برای شیفتیار کردی).
3. `phonebook-launcher.cmd` را دابل‌کلیک کنید و گزینه ۱ (پس‌زمینه) یا ۲ (پنجره با لاگ زنده) را بزنید.
4. بار اول: اگر Releaseای منتشر شده باشد، لانچر خودش `app\` را دانلود می‌کند؛ وگرنه فایل‌های برنامه را دستی در `app\` بگذارید. `data\` و `logs\` خودکار ساخته می‌شوند.
5. در اولین اجرا، کاربر `admin` با رمز تصادفی ساخته و یک بار در ترمینال چاپ می‌شود؛ در اولین ورود رمز را عوض کنید.
6. آدرس: `http://127.0.0.1:3001`
7. به‌روزرسانی: لانچر پیش از هر اجرا `update.ps1` را صدا می‌زند؛ فقط `app\` عوض می‌شود — `data\`، لانچر و لاگ‌ها دست نمی‌خورند و نسخه قبلی در `app_old\` می‌ماند. با آرگومان `auto` (مثلاً از شورت‌کات Startup) بدون منو و بدون مرورگر اجرا می‌شود.
